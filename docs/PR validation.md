## Воспроизводимые проверки

```powershell
uv sync --extra dev --extra messengers --extra office --extra huggingface
uv run --no-sync pytest -q --tb=short
uv run --no-sync python scripts/acceptance.py --mode offline
```

Зелёный pytest не означает зелёную полную приёмку: часть тестов проверяет,
что диагностический стенд корректно обнаруживает известные ошибки. Offline
acceptance ожидаемо показывает четыре открытые регрессии, перечисленные ниже.

Ruff проверяется на новых/изменённых платформенных модулях, примерах, скриптах
и их тестах, без переформатирования несвязанных upstream-файлов.

При подготовке PR: **333 passed in 95.51s**, профильная Ruff-проверка прошла,
`uv build --no-sources` собрал wheel и sdist. Это локальные автоматические
проверки, не подтверждение успешного доступа к внутренней модели.

В живом Telegram-прогоне подтверждены команды, исходящие сообщения и разбиение
длинного текста, typing, edit/delete собственных тестовых сообщений, PNG/DOCX
на выходе, callback, DOCX и текстовый PDF на входе. Вызовы внутренней модели
в сохранённых прогонах имели ошибки TLS; в одном более позднем прогоне получен
HTTP 401. Владелец сообщил об оставшейся проблеме API-ключа vLLM. Успешная
повторная end-to-end проверка этого провайдера ещё не подтверждена.

Прямые вызовы 302.ai проверялись ранее (см. `Platform validation.md` и
`Extraction validation.md`); это не новый живой прогон при подготовке PR.
Живая приёмка VK и полные сценарии исходных ботов не подтверждены.

## Открытые замечания перед финальным merge

- Нефильтрованные обработчики адаптеров Telegram/VK могут перехватывать
  события до пользовательских обработчиков SDK.
- Telegram animation/video_note не нормализуются в общий список вложений;
  MIME анимированных/видеостикеров требует корректировки.
- VK callback содержит conversation-local ID, но edit/delete принимают
  глобальный ID. В живом стенде удаляются только сообщения с ID, полученным
  от собственного send; опасный callback-путь проверяется только без сети.
- Общий интерфейс не покрывает все методы/события API; часть доступна только
  через native SDK/call_api. Наличие этого выхода не доказывает полное покрытие.
- Есть изменения контрактов: send возвращает IDs, а LLMProvider включает
  метод vision. Сторонним реализациям может понадобиться адаптация типизации.
- Нужно закрыть доступ/авторизацию внутреннего провайдера, повторить живые
  проверки fallback/vision и сверить реальные тарифы.

По явному запросу владельца acceptance-бот отвечает всем пользователям в
исходном чате. Общий лимит логических LLM-вызовов сохранён; `/finish` от любого
участника завершает тестовый процесс. Использовать отдельного тестового бота.

## Секреты и данные

В ветку включаются только код, тесты, документация и пустые env-шаблоны.
Локальные `.env`, `.env.acceptance`, `artifacts/`, `data/`, базы SQLite,
реальные входные документы и credentials не публикуются. Из env-шаблона
убран фактический адрес внутреннего хаба. Флаг `publication_allowed=false`
в диагностических отчётах не переключается автоматически: стенд не принимает
решение о merge/deploy за владельца.
