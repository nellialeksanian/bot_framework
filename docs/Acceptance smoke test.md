# Ручная проверка перед merge

`scripts/acceptance.py` — самостоятельный стенд поверх установленного `botkit`.
Исходные боты и рабочие данные не изменяет. Не делает commit/push/merge.
Без `--live` нет обращений к моделям и мессенджерам. Используйте только
выделенные тестовые токены; второй polling-процесс на том же токене недопустим.

## 1. Подготовка

Команды выполнять из корня `bot_framework_repo`:

```powershell
uv sync --extra dev --extra messengers --extra office
Copy-Item .env.acceptance.example .env.acceptance
```

Выполните копирование только один раз, если `.env.acceptance` ещё не существует.
Если локальная конфигурация уже существует, редактируйте её, не перезаписывая
повторным копированием шаблона. Реальный адрес внутреннего хаба укажите самостоятельно.
Заполните файл. Можно передать другой файл через `--env "C:/path/to/.env"`.
Значения из указанного файла имеют приоритет над окружением; отсутствующие
переменные могут наследоваться из окружения процесса. `.env` автоматически не ищется.

Минимум для моделей: адрес, ключ и имя основной модели, имя резервной модели
на хабе либо включённый прямой резерв 302.ai с его ключом и моделью.
Все модели, которые входят в цепочку, должны поддерживать изображения.
Если резерва нет, тест fallback явно завершится ошибкой, а не зелёным пропуском.
Прямой доступ к 302.ai не проверяется, если его нет в настроенной цепочке.

Для мессенджера нужен только его токен. **Бот принимает обращения от любых
пользователей и чатов**, отвечает в тот чат, откуда пришло сообщение.
Chat/user ID заранее указывать не нужно; старые `ACCEPTANCE_*_CHAT_ID` и
`ACCEPTANCE_*_USER_IDS`, если остались в локальном env, игнорируются.
Telegram: пользователь должен начать диалог с ботом. VK: включите сообщения сообщества и Long Poll
с событиями `message_new` / `message_event`. В режиме Telegram скрипт проверит,
что webhook не установлен, и **не будет самостоятельно его удалять**.

У хаба сохраняются пауза минимум 2 секунды и выключенный streaming.
`LOCAL_HUB_VERIFY_SSL=false` можно выставить явно, если требуется повторить
предоставленный пример внутреннего сервера; предпочтительнее установить CA.
Скрипт не отключает проверку сертификата автоматически.

## 2. Проверить настройки без сетевых запросов

```powershell
uv run --no-sync python scripts/acceptance.py --mode check --env .env.acceptance
```

Проверяет сборку конфигурации LLM, не доказывает доступность сервера, правильность
ключа или права мессенджера. Токены и URL в консоль/JSON не выводятся.

## 3. Локальные документы и известные регрессии

```powershell
uv run --no-sync python scripts/acceptance.py --mode offline
```

Не читает env-файл и не обращается к сети. Создаёт небольшие синтетические TXT,
DOCX, PNG, текстовый PDF и PDF-скан. Проверяет извлечение текста и PDF → PNG.
Реальные SDK с подменённым HTTP проверяют перехват обработчиков Telegram/VK,
потерю animation/video_note и передачу callback-local ID VK как глобального ID.

**На текущей реализации эти регрессионные проверки могут быть красными.**
Это намеренно: стенд фиксирует ранее найденные ошибки и не маскирует их.
Сам скрипт адаптеры не исправляет. Зелёный live smoke не отменяет красную регрессию.

## 4. Реальные модели, изображения, PDF и fallback

```powershell
uv run --no-sync python scripts/acceptance.py --mode models --env .env.acceptance --live
```

Запросы могут быть платными. Проверяются:

- Каждая модель цепочки отдельно: текст, PNG, PDF-скан через A5. Резерв не скрывает
  неисправную основную модель. Проверяются ожидаемый текст и числа на картинке.
- Обычный вызов настроенной цепочки.
- Принудительный отказ основной модели: локально подменяется HTTP-ответ на 503,
  затем вызывается **настоящий настроенный резерв**, для текста и изображения.
  Это проверка обработки отказа, а не намеренное выключение реального сервера.
- Запись событий A2, контекст, отсутствие исходных текстов в журнале.

Для N провайдеров: 3×N отдельных логических запроса, один вызов цепочки и два
вызова с принудительным fallback. Реальных запросов может быть больше из-за
резервов/повторов. В шаблоне повторы выключены, но порядок fallback не меняется.
Передаются только синтетические файлы стенда, не файлы из старых ботов.

## 5. Проверить настоящего бота

Запускайте платформы последовательно, в отдельных тестовых чатах:

```powershell
uv run --no-sync python scripts/acceptance.py --mode telegram --env .env.acceptance --live
uv run --no-sync python scripts/acceptance.py --mode vk --env .env.acceptance --live
```

Скрипт начнёт polling без предварительной рассылки сообщений. Напишите боту
с любой учётной записи и выполните шаги:

1. `/start` — получить инструкцию.
2. `/smoke` — отправка текста, длинного сообщения с emoji, typing, редактирование
   и удаление **только созданного этим тестом сообщения**, отправка PNG/DOCX.
3. Нажать кнопку «Проверить» — входящий callback и ответ на него.
4. Отправить обычный текст — проверить получение сообщения.
5. `/llm` — реальный запрос к настроенной цепочке моделей.
6. Отправить `text.pdf`, `scan.pdf`, `sample.docx`, `sample.png` из каталога
   `artifacts/acceptance-.../fixtures`. PNG отправьте как фото или файл.
   Скрипт обработает вложения A5 и сообщит PASS/FAIL без копирования их текста.
7. `/status` — посмотреть непройденные пункты; `/finish` — сохранить итог и остановиться.

Можно использовать собственные **тестовые** документы. Изображения и сканы
будут отправлены настроенной модели/резерву, в том числе 302.ai, если включён.
Не отправляйте конфиденциальные данные. Поддерживаемый входящий файл не означает
проверку содержательной правильности ответа экспертом.

По умолчанию сессия длится 15 минут и допускает максимум 10 логических вызовов
модели **суммарно для всех пользователей** (страницы vision тоже учитываются).
Изменение: `--seconds 1800 --max-calls 20`.
Повторы/fallback могут увеличить число физических запросов относительно этого
лимита. `/finish` от любого пользователя, Ctrl+C или таймаут прекращают polling
всего тестового процесса; Ctrl+C возвращает код 130. Не выполненные пункты остаются
незавершёнными. Отчёт общий для процесса; ответы и callback-кнопки привязаны к
своему чату. Любой пользователь может расходовать общий лимит платных запросов.

Callback проверяет получение/подтверждение, **не исправность редактирования по
callback ID VK**: для безопасности этот ошибочный путь не вызывается в живом чате.
Он проверяется отдельно без сети в режиме `offline`.

## Отчёт

Каждый запуск создаёт новый игнорируемый Git каталог `artifacts/acceptance-.../`:

- `report.json` — результаты, непройденные пункты, типы ошибок, сводные usage;
- `usage.sqlite3` — события A2 без исходных текстов запросов/ответов;
- `fixtures/` — созданные тестовые документы и картинка отрисованного PDF.

`report.json` можно передать для разбора. SQLite оставьте локально: там могут быть
user/chat ID и имена участников. Ошибки намеренно записываются без traceback и
текста исключения, поскольку SDK может включать в них ключи или подписанные URL.
`http_status` сохраняется, когда он доступен. `UNKNOWN_*` в стоимости не означает
нулевой расход; тарифы задаются отдельно в `config/prices.json`.

Код выхода 0 означает успех **выбранного режима**; 1 — провал/незавершённость,
2 — неверные аргументы. Ошибка не исчезнет из отчёта после удачного повтора в
той же сессии: для чистой повторной приёмки запустите новую сессию.

`publication_allowed` всегда `false`: стенд не подменяет решение о merge.
Перед merge нужны устранение регрессий, живые проверки обеих платформ,
полные сценарии конкретных ботов и сверка биллинга. ASR, все API-методы,
модерация, платежи, webhooks и полноценные B1–B5/C1 сценарии этим smoke не сертифицируются.
