# Последние изменения botkit

Этот журнал относится к библиотеке `bot_framework`, а не к отдельным ботам.
Даты разделяют новое обновление и изменения, уже находящиеся в основной ветке.

## 2026-09-30 — Pneuma ASR и доработка транскриптов

Ветка обновления: `codex/pneuma-asr-pipeline`, база `origin/main` — `c61c957`.
Изменения предназначены для review; публикация ветки не является merge или
подтверждением готовности внешних сервисов к production.

### Распознавание аудио

- Добавлены `PneumaConfig`, `PneumaTranscriber` и фабрика `load_transcriber()`.
  Поддерживаются прямой legacy API и веб-прокси; адрес и доступ задаются через env.
- Добавлен `ChunkedPneumaTranscriber` для протокола из предоставленных примеров:
  создание `/uploads`, отправка частей через PATCH с `Upload-Offset`, проверка
  смещения, завершение загрузки, ожидание `/transcriptions` и получение результата.
- При потерянном ответе клиент сверяет состояние известной загрузки/задачи,
  не создаёт новую задачу безусловно. Потерю самого первого upload ID восстановить
  нельзя; автоматический повтор такого POST намеренно не выполняется.
- Добавлены `UploadStore`, `MemoryUploadStore` и `SQLiteUploadStore`: состояние
  загрузки может переживать перезапуск; TTL 24 часа. Сохраняются только служебные
  ID/смещения/хеш, не аудио, транскрипты и ключи. Повторно предоставить байты должен
  вызывающий бот; это не очередь фоновой обработки и не распределённая блокировка.
- Ограничены размеры файлов/ответов, ожидание операции и отдельных запросов.
  TLS проверяется по умолчанию, переходы по redirects отключены.
  Для обработки аудио не требуется устанавливать локальную нейросеть/CUDA.

### Доработка через LLM

- Добавлены `LLMTranscriptProcessor`, `TranscriptResult`, `TranscriptProcessor`
  и `TranscriptionPipeline` поверх существующего A1 gateway.
- Доработка включается отдельно через `ASR_POSTPROCESS_ENABLED=true`;
  используются настройки локального `hub`, `vllm` или `openai_compatible`.
  Автоматический fallback в 302.ai для этого этапа отключён.
- Стандартная обработка восстанавливает пунктуацию/регистр. `validate_transcript()`
  проверяет сохранение слов, их порядка и числовых литералов; при содержательных
  изменениях возвращается исходный текст. Это защитная проверка, не доказательство
  точности распознавания или полной смысловой эквивалентности.
- Исходный ASR-текст сохраняется в `result.raw`, результат обработки —
  в `result.response`. Метаданные сообщают, применена ли доработка и почему.
- `arequest()` позволяет приложению объединить обработку и собственную
  классификацию в один запрос с обязательной валидацией. Доменные категории
  нежелательных намерений и статичные ответы остаются в коде конкретного бота.

### A5, runtime, учёт и тестирование

- A5 распознаёт дополнительные аудио MIME/расширения и сигнатуры;
  поддерживает голосовые, MP3, OGG/Opus, WAV, M4A, FLAC, AAC, WMA и audio/webm.
  Декодирование конкретного кодека зависит от сервера Pneuma.
- Для ASR добавлен отдельный `EXTRACTION_AUDIO_TIMEOUT`, независимо от vision.
  A5 возвращает обработанный транскрипт и метаданные, сохраняя предупреждение
  `audio_transcript_unverified` и низкую уверенность источника.
- CLI/runtime автоматически подключает выбранный ASR и корректно закрывает
  созданные клиенты. Существующие контракты без ASR продолжают работать.
- A2 учитывает ASR/постобработку: ошибки, задержки, число опросов и доступные
  метаданные. Токены LLM учитываются отдельно; неизвестная стоимость ASR не
  объявляется нулевой. Сам клиент Pneuma не пишет транскрипты в usage-лог.
- Добавлен `examples/transcribe_audio.py`; отправка возможна только с `--live`.
  В acceptance-стенд добавлены голосовые/MP3 и общий бюджет ASR + LLM вызовов.
- Расширены тесты HTTP-контрактов, возобновления, хранилищ, валидации транскрипта,
  подключения к A5/runtime и нормализации аудио реальными SDK Telegram/VK.
- Обновлены env-шаблоны, README и документация
  [Pneuma ASR](docs/Pneuma%20ASR.md), [A5](docs/Extraction%20A5.md),
  [acceptance](docs/Acceptance%20smoke%20test.md).

### Совместимость и ограничения

- По умолчанию ASR не включён; при выборе Pneuma сохраняется legacy-протокол.
  Для нового API нужно явно задать `PNEUMA_UPLOAD_PROTOCOL=chunked`.
  LLM-постобработка также включается отдельно, без скрытой смены поведения.
- Новая живая приёмка Pneuma/локальной LLM при публикации не проводилась.
  Новые ASR/LLM-тесты используют имитацию HTTP и не подтверждают доступность сервера.
- Офлайн acceptance по-прежнему обнаруживает четыре ранее документированные
  проблемы A4: передачу событий пользовательским обработчикам Telegram/VK,
  нормализацию Telegram animation/video_note и использование conversation-local
  ID из VK callback в edit/delete. Эти участки адаптеров не изменены относительно
  `main`; зелёный pytest не означает закрытие всех замечаний acceptance.
- В исходных upstream-модулях вне этого обновления остаются замечания общего
  Ruff-прогона. Профильные изменённые Python-файлы проверяются отдельно.
- Ключи, пользовательские данные, локальные env, отчёты с runtime-данными,
  Docker-поставка Сократика и код других ботов в это обновление не входят.
- Yandex/Google TTS и доменная политика Сократика не объявляются новыми
  универсальными модулями этой библиотеки: они находятся в отдельном приложении.

### Проверки подготовки обновления

- Полный pytest на базе свежего `main`: **460 passed in 44.58s**.
  Для существующих RAG-тестов использовалась закешированная модель с
  `HF_HUB_OFFLINE=1` и `TRANSFORMERS_OFFLINE=1`: системный DNS был недоступен.
- Ruff check и Ruff format --check: все **21 изменённый Python-файл** прошли.
- `uv build --no-sources --offline --no-build-isolation`: wheel и sdist собраны
  локальным установленным backend; новые публичные классы импортируются из wheel.
- Проверка подготовленного дерева и дистрибутивов не обнаружила совпадений
  с проверяемыми реальными ключами из локальных env; сами env исключены из Git.
- Отдельный offline acceptance: четыре известных замечания A4, перечисленных
  выше, остаются открытыми; итог стенда **failed**, `publication_allowed=false`.
  Этот флаг не менялся вручную. Ветка публикуется по явному запросу владельца,
  не как автоматическое разрешение на merge/deploy.

## 2026-09-29 — числовые оценки B3, уже в main

Upstream-коммит `c61c957`, сохранён при подготовке нового обновления:

- У критериев появились допустимая шкала `score_scale` и правило `scoring_rule`.
- `RaterRecord` и `record_rating()` поддерживают словарь числовых `scores`.
- SQLite сохраняет оценки в `scores_json`; добавлена совместимая миграция
  существующих таблиц и чтение прежних пакетов критериев.
- Изменение шкалы/правила учитывается при версионировании пакетов; правила
  выводятся в текст критериев для модели.
- Добавлены проверки обратной совместимости и сохранения/чтения оценок.

## 2026-09-23 — A1/A2/A4/A5, уже в main через PR #1

- A1: общий gateway для 302.ai, хаба и OpenAI-compatible/vLLM; изображения,

  маркировка неизвестной стоимости.

  с сообщениями; доступ к native SDK/call_api с перечисленными выше ограничениями.
- A5: документы и Office, извлечение текста PDF или PDF → PNG → vision,
  ограничения ресурсов и интерфейс подключаемого ASR.
- CLI, примеры, документация миграции и acceptance-стенд.
